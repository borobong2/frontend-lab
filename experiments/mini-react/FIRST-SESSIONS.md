# 첫 두 세션 진행 카드

시작 위치는 experiments/mini-react입니다. 실행 방법은 [레포 안내](../../README.md#바로-시작)를 따릅니다. 아래 빈칸은 학습자가 채우며, 제공된 코드를 본인 구현으로 기록하지 않습니다.

## 세션 1 프론트와 React의 책임

### 실행 전에 15분

[React가 필요한 이유](WHY-REACT.md)를 읽기 전에 먼저 적으세요.

- 사용자가 성공했다고 판단할 수 있는 조건:
- 화면이 기억해야 하는 값:
- 다른 값에서 계산할 수 있는 값:
- React를 도입하면 줄어들 것으로 예상하는 일:
- React를 써도 내가 책임져야 하는 일:

### 화면 관찰 10분

키보드 검색 → 재고 필터 → 검색 해제 → USB 허브 메모 → 역순 정렬 순서로 조작합니다. 각 행동 전에 결과 개수와 메모의 위치를 예상합니다.

### 코드 추적 20분

main.js에서 이벤트 리스너 → updateResults → filter/sort → replaceChildren → 노드 생성 → 개수 표시를 찾습니다. 호출 순서를 한 번 직접 그립니다. 메모의 저장 위치와 검색 입력값의 저장 위치가 같은 방식인지 비교합니다.

### 통제 실험 30분

한 번에 하나만 바꿉니다. 결과 개수 갱신을 잠시 빼고 불일치를 관찰한 뒤 복구합니다. 이어 목록 갱신 전 DOM 노드 참조를 저장하고, 갱신 후 같은 노드인지 비교합니다. 성능이 좋아졌다는 결론은 측정 없이 내리지 않습니다.

### 기록 15분

[기록 양식](../../notes/TEMPLATE.md)을 복사해 예상과 실제가 다른 한 가지를 적습니다. 프론트·브라우저·프레임워크의 책임을 내 말로 3분 설명합니다. 블로그 발행은 필요 없습니다.

## 세션 2 UI를 데이터로 표현

### 회상 10분

이전 메모 없이 상태와 DOM을 맞추는 책임을 설명합니다. 막힌 부분만 이전 기록을 확인합니다.

### 계약 정하기 15분

h()는 무엇을 반환하고, mount()는 언제 DOM을 만드나요? 문자열·숫자·중첩 태그·클릭 이벤트만 지원한다고 적고, 입력과 결과 모양을 종이에 그립니다.

### 구현과 확인 45분

[단계 1](MISSIONS.md#1-ui-설명-객체와-렌더러)의 요구를 충족하는 최소 구현을 시작합니다. 원본 화면과 비교하려면 원본을 보존한 채 작은 별도 HTML에서 실험할 수 있습니다. 이 단계에는 JSX·diff·훅이 필요 없습니다.

### 설명과 다음 질문 20분

UI 설명을 두 번 만들었다고 실제 DOM도 반드시 두 번 생성되어야 하나요? 전체 DOM을 교체하는 갱신 방식을 붙인다면 어떤 사용자 상태를 잃을까요? 아직 구현하지 않은 것은 예측으로 표시합니다.

## 도움을 요청하는 형식

```text
지금 단계:
사용자 성공 조건:
내 예상:
실제 결과와 최소 코드:
내 가설:
전체 정답 대신 확인할 관찰값 하나와 힌트 하나를 주세요.
```

90분 후 끝나지 않으면 현재 상태와 다음 실험만 남기세요. 밀린 전체 과정을 숙제로 이월하지 않습니다.

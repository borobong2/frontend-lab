# React를 왜 쓰는가

목표는 UI와 상태를 일관되게 연결하는 책임을 직접 경험하는 것입니다. 이 실험의 작은 구현은 실제 React 내부 구현과 동일하지 않습니다.

## 학습 자료

[왜 React인가](WHY-REACT.md) → [첫 두 세션](FIRST-SESSIONS.md) → [단계별 구현 과제](MISSIONS.md) 순으로 진행합니다. 상세 과제는 요구사항만 제공하며 정답 코드는 포함하지 않습니다.

## 제공된 출발점

`index.html`은 검색·재고 필터·가격 정렬·행별 메모 화면이고, `src/main.js`는 DOM을 직접 조작합니다. 데이터는 합성 상품 5개입니다. React·JSX·서버 API·저장은 없습니다. 새로고침하면 메모가 초기화됩니다.

현재 구현은 이벤트마다 목록을 재생성하고, 메모는 상품 ID별 객체에 보관합니다. 이는 비교를 위한 단순한 출발점입니다. 부모 전체를 교체할 때와 목록만 교체할 때의 차이를 다음 실험에서 확인하세요.

## 첫 세션 90분

1. **15분:** 코드를 열기 전에 화면을 사용하고 검색어·필터·목록·결과 개수·메모 중 원본 상태와 계산 가능한 값을 적습니다. 사용자·브라우저·JS·서버의 책임도 나눕니다. 현재 예제에는 서버가 없습니다.
2. **10분:** 검색 후 메모를 쓰고 정렬·필터를 바꾸면 무엇이 유지될지 예상합니다.
3. **10분:** 아래 공식 문서의 최소 상태와 상태 소유자 부분을 읽습니다.
4. **40분:** `main.js`에서 이벤트 → 데이터 선택 → DOM 변경을 추적합니다. 작은 변경 하나로 화면 갱신 책임이 누락되는 상황을 만들고, 원인을 확인한 뒤 되돌립니다.
5. **15분:** 기록 양식에 예상·실제·설명 변경·다음 질문을 남깁니다.

첫 세션에는 렌더러를 완성할 필요가 없습니다. 다음 세션은 `h()`로 UI를 표현하고 전체 DOM 교체 시 포커스가 어떻게 되는지 확인합니다.

## 구현할 단계

아래는 앞으로 직접 구현할 과제입니다. 시간표가 아니라 순서이며, 한 단계가 여러 세션이 되어도 괜찮습니다.

| 단계 | 구현할 작은 범위 | 관찰할 실패·완료 조건 |
|---|---|---|
| 0 | 제공된 JS 화면 읽기·작은 변경 | 상태와 DOM 갱신 위치를 설명 |
| 1 | h(type, props, children), 텍스트·요소 렌더러 | UI 설명과 실제 DOM을 구분; JSX 파서는 제외 |
| 2 | 함수 컴포넌트·props·children | 동일 함수 두 개를 다른 props로 렌더링 |
| 3 | 상태 저장과 갱신 요청 | 변수 변경만으로 화면이 바뀌지 않는 이유 설명 |
| 4 | 타입·텍스트·속성·이벤트 patch | DOM 참조·입력 포커스 유지, 제거된 이벤트 중복 방지 |
| 5 | 형제 목록의 key 대응·이동·삭제 | 순서를 바꿔도 각 항목의 메모·상태 유지; key 변경 시 초기화 |
| 6 | 인스턴스별 useState와 훅 순서 | 같은 컴포넌트 두 개의 상태 독립; 조건부 훅 오류 재현 |
| 7 | 의존성 비교·effect·cleanup | 의존성 변경·제거 시 타이머/구독 정리; 정확한 React 실행 시점 재현은 제외 |

처음 지원 범위는 HTML 요소·문자열·숫자·간단한 이벤트입니다. 특수 폼 속성·빈 자식·배열 등은 실제 예제가 필요로 하는 순서로 추가하고 한계를 기록합니다. `key`는 형제 사이의 정체성을 다루며 전역 고유 ID로 설명하지 않습니다.

Fiber·동시성·Suspense·SSR·hydration·컴파일러는 제외합니다. batching·업데이트 큐는 기본 상태가 이해된 뒤 선택합니다. React를 재구현했다고 해서 항상 더 빠르다고 주장하지 않습니다.

## 수동 확인

출발점을 수정했을 때 확인합니다.

- [ ] 최초 목록 5개, 결과 개수 5개.
- [ ] `키보드` 검색 시 2개, 재고만 선택하면 1개.
- [ ] ` USB ` 검색 시 USB 허브 1개 (양끝 공백 무시, 영문 대소문자 구분 없음).
- [ ] 없는 이름은 0개와 빈 결과 안내. 검색을 비우면 다시 표시.
- [ ] 가격 낮은 순·높은 순이 서로 반대이며, 기본 순서로 복귀.
- [ ] 메모 입력 후 정렬·검색에서 숨김/복원해도 같은 상품에 메모 유지.
- [ ] 검색에 `<img src=x>`를 입력해도 HTML로 실행되지 않음.
- [ ] Tab과 키보드로 입력·선택 가능, 좁은 화면에서도 조작 가능.
- [ ] 새로고침 시 검색 조건·메모 초기화 (현재 저장하지 않음).

## 공식 근거와 비교

- [Thinking in React](https://react.dev/learn/thinking-in-react): 컴포넌트·최소 상태·소유자.
- [createElement](https://react.dev/reference/react/createElement): DOM이 아닌 UI 설명 객체.
- [Render and Commit](https://react.dev/learn/render-and-commit): 계산과 DOM 적용의 구분.
- [Preserving and Resetting State](https://react.dev/learn/preserving-and-resetting-state): 위치·타입·key와 상태.
- [State: A Component’s Memory](https://react.dev/learn/state-a-components-memory): 상태와 훅.
- [Synchronizing with Effects](https://react.dev/learn/synchronizing-with-effects): 외부 동기화와 cleanup.
- [Build your own React](https://pomb.us/build-your-own-react/): 막힌 구현을 비교할 교육용 참고. 현재 React 구현의 명세가 아님.

매 단계에서 우리 모델의 지원 범위와 실제 React와의 차이를 기록합니다. 실제 React 비교는 공식 샌드박스나 별도 예제로 하고, 비교한 버전과 결과를 남깁니다.
